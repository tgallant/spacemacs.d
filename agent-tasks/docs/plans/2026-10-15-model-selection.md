# Model Selection Implementation Plan

> **REQUIRED SUB-SKILL:** Use the executing-plans skill to implement this plan task-by-task.

**Goal:** Allow Emacs and spawn_task callers to pin a task's pi model, including an optional thinking suffix.

**Architecture:** Persist the requested pattern, forward it across the JSON boundary, and let pi resolve it through session-local CLI arguments. Validate the resulting selection through RPC before sending a prompt. For pinned resumes, start with both --session and --model (explicit CLI selection wins over session history), then load pilish history without issuing switch_session. Keep legacy default-model behavior unchanged.

**Tech Stack:** Emacs Lisp/ERT, pilish RPC, TypeScript/node:test.

## Design choices

- CLI resolution preserves pi's exact/fuzzy/provider and thinking-suffix semantics without implementing a second resolver in Lisp. RPC-only selection would require duplicating pattern resolution.
- CLI alone is insufficient: pi can synthesize a custom model for an unknown ID on a known provider. Compare get_state's selected provider/id against get_available_models; report failures synchronously and kill failed session buffers.
- Store the requested pattern rather than global settings or runtime pilish state. A nil model means pi's default; older persisted tasks load with nil. Show `default` for unpinned tasks and blank for untracked sessions.
- Interactive completion reads enabledModels from PI_CODING_AGENT_DIR/settings.json or ~/.pi/agent/settings.json. Completion is advisory: callers can enter other valid pi patterns or thinking suffixes. Missing settings means no candidates; malformed settings reports the file and parsing error.

## Verification results

- Test-first: new propagation/adapter/UI tests failed before implementation;
  additional regressions demonstrated that blank patterns and reused live
  sessions could otherwise silently use a different model.
- `make test`: 58 ERT, 9 node tests and all 8 install checks pass.
- `emacs -Q --batch -L agent-tasks --eval '(setq byte-compile-error-on-warn t)' -f batch-byte-compile agent-tasks/agent-tasks.el`:
  clean compilation; generated bytecode removed.
- Real isolated Emacs with installed pilish and pi, using a throwaway git repo
  under `/tmp`: spawned `openai-codex/gpt-6-astra:high`, received `OK`, checked
  both RPC and `(plist-get pilish--state :model)` and thinking level.
- Changed the saved session to `openai-codex/gpt-6.1-sol` via RPC, killed the
  session, loaded persisted task metadata and resumed. The task returned to
  Astra/high with the same session file and rendered history. This verifies
  that CLI `--session` plus `--model` takes precedence over saved selection.
- Unknown known-provider ID (`openai-codex/not-a-real-model-xyz`) returned
  `Unknown or unavailable pi model` through the JSON reply. Unknown provider
  returned pi's startup diagnostic through the JSON reply. Neither left a
  running session or registered task, and neither sent the task prompt.
- A pinned start refuses an existing live session rather than silently reusing
  it (pilish would ignore new CLI arguments). Verified against real pilish.
- All throwaway tasks, worktrees, git repos and pi session logs were removed.
  Pi session storage was explicitly redirected beneath each throwaway root.
